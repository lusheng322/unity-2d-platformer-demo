# 架构总览与项目讲解稿

> 用途：① 自己复习时快速回忆三条设计主线；② 面试"讲讲你的项目"时照着讲（3 分钟版在最下面）。

---

## 一、三条设计主线

### 1. 状态机（State 模式）

- `PlayerStateMachine` 只做三件事：持有 `currentState`、`Initialize()`、`ChangeState()`（先 `Exit()` 旧状态，再 `Enter()` 新状态）。
- 每个状态是一个独立类（`PlayerIdleState` / `PlayerMoveState` / `PlayerDashState` / `PlayerPrimaryAttack` / `PlayerBlackholeState` …），各自实现 `Enter / Update / Exit`。
- 动画事件（Animation Event）回调 `Player.AnimationTrigger()` → `stateMachine.currentState.AnimationFinishTrigger()`，用**动画的真实结束点**驱动状态切换，而不是用计时器猜动画长度。
- 敌人用同一套思路（`EnemyStateMachine` + `Enemy_Skeleton` 的 Idle/Move/Battle/Attack/Stunned 状态）。

**为什么这么写**：新增状态不需要修改已有状态（开闭原则）；每个状态的进入/退出逻辑集中在一处，不会散落成一堆 `if`；同一套模式可以复用到敌人。

### 2. 技能系统三层分工

| 层 | 类 | 职责 |
|---|---|---|
| 数据层 | `Skill`（基类）、`Sword_Skill` / `Clone_Skill` / `Crystal_Skill` / `Blackhole_Skill` / `Dash_Skill` | 冷却计时（`IsReady` / `CanUseSkill`）、参数配置（Inspector）、生成技能产物 |
| 分发层 | `SkillManager`（单例） | 集中持有所有技能并提供访问入口；同时承载"便于微调"的全局参数（如水晶生成间隔） |
| 表现层 | `Xxx_Skill_Controller` | 技能产物的运行时行为：飞行/追踪/爆炸/生命周期 |

**为什么这么写**：数据与表现分离——`Blackhole_Skill` 不知道黑洞长什么样、怎么收缩；`Blackhole_Skill_Controller` 不知道自己是被哪个技能放出来的。换表现不用动数据层。

### 3. 基类复用（Entity）

- `Entity` 统一处理"会被打的物体"：组件缓存（`rb`/`anim`/`sr`/`fX`）、受击闪白、击退、地面/墙体/攻击范围检测、翻转。
- `Player : Entity`、`Enemy : Entity`，各自只实现差异部分。
- 敌人血量与死亡也收敛在 `Enemy` 里（`Damage()` → `Die()`），玩家不受影响。

## 二、面试可讲的三个技术点（都在代码里有证据）

1. **状态机为什么比 switch/if 好**：每个状态独立类、`Enter/Update/Exit` 分工明确、新增状态不改老代码；而且这套结构可以直接复用到敌人（我的骷髅敌人就是自己一套状态机）。
2. **技能系统为什么分三层**：数据（冷却/参数）→ 分发（`SkillManager`）→ 表现（Controller），换表现不动数据；`SkillManager` 还把技能引用放在 `Awake()` 里初始化（所有 `Awake` 都早于任何 `Start`，避免别的脚本在 `Start/Update` 里取技能时空引用）。
3. **我主动修过的问题**（比"我实现了什么"更有说服力）：
   - 黑洞的 QTE 键位池里含有 `F`，而水晶当时绑定在 `F` 上 → 按 QTE 会顺手放技能。**根因是技能输入没有统一的"什么时候能放"约束**，而不是键位写错。
   - 剑扔出去命中敌人后不回来、几秒后直接消失：`bounceSpeed` 太慢 + 写死 7 秒销毁；后来我自己一次改动还引入了"刚扔出去就飞回来"的回归，靠新增 `bounceActive`（区分"配置为弹射"和"已经进入弹射阶段"）修掉。
   - 原版黑洞有个隐患：黑洞被 `Destroy` 时 Unity **不会补发 `OnTriggerExit2D`** → 被冻结的敌人会永久停住。我在收尾和 `OnDestroy` 里都手动解冻。

## 三、3 分钟项目讲解稿（可直接背）

> **定位**（15 秒）
> "这是我用 Unity 2022 + C# 做的一个 2D 平台动作 demo。我是跟着一套系统教程完成的，但不止抄：核心玩法、技能系统、敌人 AI 都在，我还自己重做了一个技能机制、修掉了一批 bug。"
>
> **架构**（60 秒）
> "整个项目有三条主线。第一条是玩家控制：用 State 模式把玩家拆成 12 个状态类，动画事件驱动状态结束，而不是用计时器猜动画时长。第二条是技能系统，分三层——数据层管冷却和参数、`SkillManager` 负责分发、每个技能还有一个 Controller 管产物的表现和生命周期，比如水晶的追踪与爆炸、黑洞的展开与收缩。第三条是 `Entity` 基类，玩家和敌人共用受击、击退、地形检测这些通用逻辑，各自只写差异。"
>
> **我自己做的改造**（45 秒）
> "黑洞技能原版是给每个敌人头顶弹一个 QTE 键，让玩家一个个按——我觉得太老式，改成：黑洞展开完成后在角色头顶提示，再按一次 R 就对黑洞内每个敌人各打一次，并且等所有分身攻击播完才收尾。水晶原来是用按键释放，我改成闪避时在起点依次生成三个水晶自动攻击附近敌人。这两处都涉及输入隔离——R 同时用于起手和发动，我用状态隔离 + `IsActive()` + 冷却三层保证一次按键只有一个阶段能读到。"
>
> **我排查过的问题**（30 秒）
> "举一个：剑扔出去命中敌人后卡住、几秒后消失。我一开始以为是逻辑写错，查了场景里的序列化配置才发现是弹射速度只有 2 单位/秒，而销毁定时器写死 7 秒——剑还没弹完就被销毁了。更麻烦的是我后来自己引入了一个回归：我加的'目标为空就回旋'保护逻辑，在'剑撞墙插住'这条路径上前提不成立，导致剑一扔出去就自己飞回来。最后我用一个 `bounceActive` 标记区分'配置为弹射模式'和'真的进入弹射阶段'才修掉。"
>
> **收尾**（15 秒）
> "目前缺的主要是 UI 和存档；性能上还没做对象池。这些我都记在 README 的 TODO 里。"

**小技巧**：讲到"我自己修过的问题"时，把**现象 → 我的判断 → 证据 → 根因 → 修法**说成一条线，面试官会明显更感兴趣——因为这说明你真跑过、真调过。
